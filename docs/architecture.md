# Architecture

## Current structure

- `src/main.ts` is the browser composition root. It reads `Preferences`, creates one deterministic blueprint, one hidden gameplay world, one shared scene stage, camera controller, reusable FX, powers, targeting, tray, Journal, Sfx, title, and Settings, then advances them according to the pure app-flow phase. Gameplay simulation and visual mutation run only in `gameplay`; the title, normal prologue, replay transitions, and canonical replay therefore cannot mutate the hidden island. The normal prologue set is constructed and frozen at time zero during `title`, remains visible behind the translucent Begin treatment, and the same director continues it after Begin without replacing the set. Normal completion renders one final prologue frame and one frozen gameplay frame before enabling gameplay. Settings replay saves the camera and stage pose, uses opaque title covers around an isolated prologue, and restores the same live gameplay objects afterward.
- `src/scene.ts` owns renderer creation and WebGL fallback, the shared `island-stage` root, golden-hour lighting, tightened 2048px VSM shadows, the post-processing composer, responsive perspective camera, procedural gradient sky, six cloud clusters, and reduced-motion-aware ambient stage/cloud movement. Enhanced rendering caps DPR at 1.5; reduced quality fixes DPR at 1 and bypasses shadows and post-processing.
- `src/camera/policy.ts` is the Three.js-free constrained-diorama camera policy: exact home pose, 15–55 metre dolly range, 7.5 metre horizontal target disc, distance-sensitive polar-angle ceiling, and smooth reset/recentre interpolation.
- `src/camera/controller.ts` owns `OrbitControls`, one-finger orbit, two-finger dolly/pan, pointer-centred zoom, right/middle-button panning, target/polar enforcement, exact home reset, and idle recenter-before-auto-rotate. Its composable `prologue | targeting | journal | settings` reason locks prevent one owner from accidentally unlocking another; live reduced motion disables auto-rotate and snaps any reset to home.
- `src/core/preferences.ts` owns safe access to `clayisland.visualQuality`, `clayisland.autoRotate`, `clayisland.reducedMotion`, and `clayisland.introSeen`. Reduced motion defaults from the OS only when no valid stored boolean exists, after which an explicit stored On/Off choice wins. `?lowfx=1` forces reduced quality for the session and disables quality changes; blocked storage keeps auto-rotate, reduced-motion, and intro-seen changes session-local, while a failed quality write is reported to Settings without changing the active renderer.
- `src/core/appFlow.ts` is the pure `title -> prologue -> gameplay` and covered replay state machine. Every accepted transition advances a generation token so asynchronous cover/director callbacks can reject stale work; only returning and replay prologues are skippable, and powers are armable only in gameplay without a modal owner.
- `src/core/motion.ts` reads the OS reduced-motion preference for first-run initialization and applies the live effective choice to the root `data-reduced-motion` state. The composition root supplies one effective-motion callback to camera, scene, FX, Journal, Settings, title, and prologue consumers instead of letting components query the OS independently.
- `src/core/rng.ts` provides the seedable pseudo-random source used for reproducible simulation and procedural generation.
- `src/core/noise.ts` builds deterministic 2D value noise and fractal Brownian motion from integer lattice hashing.
- `src/core/events.ts` defines the shared game-event contract and a synchronous subscription bus that safely tolerates unsubscription during dispatch.
- `src/core/loop.ts` separates fixed-step simulation from display-rate rendering and provides the 12fps quantized animation clock. Its lifecycle is idempotent: duplicate starts cannot create parallel RAF chains, and stopping from either simulation or rendering prevents any further work from being scheduled.
- `src/core/timeline.ts` schedules one-shot callbacks for the staged anticipation, impact, and aftermath beats used by powers. Events execute in timestamp order even when a caller registers them out of order.
- `src/fx/clayMaterial.ts` creates the shared toon material, including a cached soft three-band ramp and shader patches for fingerprint-scale normal breakup and hand-mixed color variation. Flat variants skip shader noise and use a distinct program-cache key.
- `src/fx/decals.ts` provides the pure numeric helpers for radial scorch accumulation and base-to-decal channel blending, keeping vertex-color painting independent of Three.js.
- `src/fx/wobble.ts` mutates a geometry once by displacing vertices along their normals with seeded, decorrelated low-frequency noise, then rebuilds its normals.
- `src/fx/emotes.ts` owns one canvas-generated seven-cell glyph atlas, including the cower performance mark, and the billboarded `EmoteSprite`. Each sprite selects an atlas cell and applies its pop, bob, and lifetime only on quantized frames.
- `src/fx/particles.ts` owns the fixed-capacity `ParticleBurst` pool: one wobbled icosahedron geometry, one clay material, and one `InstancedMesh` whose dead slots are hidden at scale zero and reused without allocation. Per-slot position, velocity, rotation, spin, gravity, size, and lifetime live in typed arrays and advance at display rate. The pool is parented to the shared stage root and consumes stage-local burst coordinates, so chips, meteor debris, and steam inherit the same ambient bob as the island.
- `src/fx/quality.ts` owns `VisualQualityController`: tilt-shift is zero at 22 metres and closer, rises smoothly to 0.45 at the home distance, and stays capped beyond it; held grain is 0.12 normally, 0.06 static under reduced motion, and advances its seed only on the shared 12fps clock. Reduced quality leaves the controller allocation-free and inert.
- `src/fx/shake.ts` provides trauma-squared noise shake with previous-offset cleanup plus a reusable DOM flash overlay. Shake reads reduced-motion live and stops without leaving camera drift; flash substitutes a soft 30%-opacity fade for the normal bright impact flash.
- `src/world/craters.ts` is the pure crater geometry contract: it calculates reusable non-stacking bowl depth and levelled ejecta-lip lift, exposes the lip's full influence radius, and resolves whether a point lies inside a crater rim.
- `src/world/terrain.ts` is the pure ground-query layer. It groups craters by transitive wet connectivity: overlapping rims share a `Basin` only when sampled ground across their saddle stays below the pair's water level. It assigns each basin one water level at its lowest sampled rim minus freeboard and exposes water-level, submersion, and buildability queries for world systems.
- `src/world/fire.ts` is the pure wildfire state machine and sole fire-tuning source. `FireSystem` advances tree/hut burn timers, performs seeded one-step-per-tick spread, protects burnt records from re-ignition, keeps campfire sources alive until doused, and returns typed ignition/burn-out/douse events while mutating plain `Flammable` records.
- `src/world/forest.ts` owns the pure tree-lifecycle vocabulary and forest recovery rules. `MAX_TREES` caps the standing population at 13, while `AUTONOMOUS_TREE_RESERVE` preserves eight standing trees from ordinary villager work; `seedSite()` uses seeded randomness and `isBuildable()` to sprout 2.5–5 metres from a surviving tree, with an island-wide mercy seed when none remain. Separate `isLiving()` and `holdsPlace()` predicates keep fire fuel and population accounting explicit even though both currently select the same standing poses.
- `src/world/charring.ts` owns `Charring`, which captures material base colors and applies one clamped scorch amount to every registered material. Driving the amount back to zero restores the exact clean colors used by rebuilt or extinguished objects.
- `src/world/island.ts` owns the procedural radial-grid grass surface, dirt fringe, rocky lathed underside, persistent crater deformation, accumulated scorch painting, and the crater-aware ground-height query used by all grounded entities. Crater and scorch stamps derive a bounded band of radial-grid indices instead of scanning every vertex.
- `src/world/scatter.ts` is the pure deterministic layout solver. It rejection-samples every new footprint against all earlier placements so trees, huts, the build site, and the central campfire cannot overlap.
- `src/world/blueprint.ts` defines `InitialWorldBlueprint`, the canonical deterministic starting contract for island seed, prop ids/states/visual seeds, villager positions/facing/visual and behavior seeds, stage rotation, and frame-132 handoff. `createInitialWorldBlueprint()` is the only source for both cinematic and gameplay initial composition.
- `src/world/initial.ts` owns `buildInitialWorld()`, which materializes the blueprint into one gameplay `Island`, `World`, prop set, and villager set. The canonical initial world contains three built huts, one lit campfire, and the matching villagers and trees. Gameplay and prologue construct their visuals independently from the same seeds, allowing exact final-transform comparison without sharing mutable objects.
- `src/world/objects.ts` defines the visual `Tree`, `Hut`, `Campfire`, `Pond`, `Grave`, and `FlowerPatch` entities from wobbled clay primitives. `TreeState` is the six-pose union `sapling | normal | burning | toppling | felled | stump`; a private `chop | fire | null` cause marker makes a chopped fall show a stump while a fire-caused fall never does. Saplings grow trunk and crown together, retain their current scale and height when fire starts their fall, both direct lightning and spread burn upright before producing a temporary charred log, and meteor obliteration expires a tree without wooden remains. A toppling trunk moves smoothly 0.9 metres along its fall direction, leaving its felled pose beside rather than through the root with the tapered trunk's broad end nearest the root; chopped logs later give way to temporary stumps. Normal trees shudder on axe strikes and hang four pickable fruit instances in stratified crown quadrants. `Tree.pickFruit(x, z)` converts the picker into crown-local space, scales only the nearest live slot to zero, and disposes the shared mesh after the fourth pick. Trees and huts expose stable `Flammable` state, share `Charring` for every owned material, and each owns one reusable flame/smoke group and shadowless point light. `HutState` includes `abandoned`, whose foundation stones remain visible until a builder arrives at replacement ground. `CampfireState` is `site | building | lit | doused | scattered`: site shows stones, building continuously scales in crossed logs, doused preserves an intact unlit fire, and scattered preserves displaced wreckage. Each `Pond` represents one basin with a terrain-clipped top and bed and owns three reusable fish meshes, a bounded `fishCount`, water-aware deterministic swim routes, individual catches, a two-second Lightning stun, and allocation-free Rain restoration. Graves age from fresh after 60 seconds. Each flower patch packs only accepted samples into one 36-instance bloom mesh; its placement predicate rejects submerged pond ground while still admitting dry crater beds. Removed object resources and expired fruit meshes are explicitly disposed.
- `src/world/world.ts` owns the small world registry and its linear spatial queries, target resolution order, shared event bus, villager alarms and meteor warnings, pure-to-visual fire-event bridge, targeted mutation, nearest-camera three-fire-light cap, step/chip-effect bridges, death-huddle cue, housing-gated repopulation, and 25–40-second forest reseeding. `capacity()` grants two places per built hut up to 12; over-capacity is legal and stable, while the zero-population `repopulationHome` mercy path ignores capacity. Only `sapling`, `normal`, and upright `burning` trees enter `World.flammables()` or count toward the forest cap; `canChopAutomatically()` admits ordinary chopping only above the eight-tree standing reserve. It is the persistent consequence boundary used by matrix handlers: it removes and disposes expired or meteor-hit trees, holds invisible hut/campfire site reservations in placement occupancy while builders travel, revalidates them on arrival, and atomically swaps old remains for visible sites only when work begins. `foundHutAt()` is the only growth path that creates a new home and independently enforces the one-pending-site invariant. The registry also exposes basin-backed submersion/depth queries, separate nearby-water and stocked-water queries, and separate bare-tree and fruit-tree queries for ground nudges; direct tree resolution retains the selected tree identity. It targets up to four idle villagers inside `NUDGE_EARSHOT`, restores fish in Rain-intersected basins, and rejects submerged samples when Rain creates flowers. Basin rebuilding preserves unchanged pond objects and sums surviving populations up to three when ponds merge. It creates and updates typed graves/ponds/flowers, grows fruit, and re-grounds props after terrain deformation.
- `src/villagers/fsm.ts` is the pure theatrical behavior selector. It fixes the villager state union at exactly twelve states, applies danger/mourning/rebuilding overrides in priority order, filters idle activities—including `makeFire`, `harvest`, and `gather`—by world availability, and supplies deterministic per-state duration ranges. Fishing requires stocked water. Autonomous chopping additionally requires the forest to be above its standing reserve, while an explicit `chop` suggestion may bypass that conservation rule. Drinking has zero ordinary idle weight and is reachable only through thirst or a valid `drink` suggestion. A `Suggestion` adds a large weight to one available action without bypassing its physical preconditions or silencing the ordinary idle roll.
- `src/villagers/model.ts` owns the deterministic `VillagerModel` mesh boundary shared by gameplay villagers and prologue actors. A visual seed produces identical named geometry, smock color, scale, and idle transforms in both contexts; authored `wake | carry | hammer | place | kneel` prologue poses always reset to the exact idle pose before handoff.
- `src/villagers/villager.ts` owns deterministic spawning around `VillagerModel`, continuous steering, activity execution, quantized transforms, emotes, and four-frame hut respawn. Transient look-up, startle, cower, flinch, intro-wake, and grief-huddle poses sit above the twelve-state FSM; the 0.25-second meteor startle hands off to `panic()` instead of freezing the walker. Steering combines object repulsion with basin depth samples and a shoreline tangent, while random and flee targets reject submerged ground. A mourner whose fresh grave becomes submerged dynamically retargets to the containing pond's dry `shoreNear()` point, completes the same mourning timer there while facing the grave, and returns to the grave if the pond disappears. One completed four-second cast consumes one fish, and its action timer cannot be cut short by the generic state watchdog; a stale fisher drinks from the still-present pond, while a removed pond cancels the activity. The lowered forward-pointing rig connects its line to the transformed pole tip and derives its float height from the target water level. Villagers interrupt labour after `THIRST_LIMIT` to perform a per-frame drink and resume it. Carried fruit is parented to the arm and has a state-independent swallow countdown, so safety and narrative overrides cannot hide it before `villager:ate`. A Nudge suggestion persists across danger and narrative overrides until its matching action completes or its selected target becomes invalid; fresh graves and ruins are checked as live priorities. Suggested gathering completes only after arrival and a visible performance, and campfire-centered suggestions are moved to a reachable ring outside solid-prop repulsion. Water suggestions choose the pond nearest their cast location. Fruiting trees are harvest-only targets for both suggestions and autonomous choice, while bare trees remain independently choppable in the same stand; if the chosen chop target fruits en route, the villager changes activity but preserves that exact tree. Autonomous choppers recheck the eight-tree reserve before the final axe blow so simultaneous workers cannot overshoot it; Nudge-directed choppers remain player-authorized exceptions. Gatherers stoop and poke at dead-fire ashes; villagers also shelter under nearby crowns, pause at old graves, and fell shuddering trees with four visible axe strikes. Choosing deferred hut or campfire work returns an invisible shared reservation to walk toward; the arriving villager commits it immediately before work, revealing the site and removing the old remains. Lightning's char/blink/tip/ghost zap resolves as a living comic recovery. Quantized walking frames call the world's injected step-foley bridge.
- `src/powers/drag.ts` owns the single reusable clay-ring reticle and raycaster. `DragTargeting` unifies pointer dragging with the keyboard reticle path, converts ray hits from the floating island's world transform back into local simulation coordinates, resolves target kinds only at the registry boundary, and maintains the target status announcement. Returning a pointer gesture to its originating power hides the reticle, replaces the visible target readout with “Release to cancel,” and marks that button with a clay × until targeting resumes or the drag is cancelled. Arrow movement is camera-relative after compensating for the island's world rotation, and changing the armed power preserves the pointer gesture captured before the tray callback.
- `src/powers/power.ts` defines the shared cast context, including the active `PowerId`, abstract `Power`, and `PowerManager`. The manager resolves targets at cast time, rejects unavailable/cooling powers, advances active three-beat timelines, and exposes normalized cooldown state to the tray.
- `src/powers/matrix.ts` is the pure, exhaustive 4-power × 7-target product table. It returns declarative `Interaction` records and exports the complete `InteractionKind` list for handler-completeness tests. Meteor-on-tree resolves to `['destroy']` alone; nearby blast ignition remains the meteor timeline's separate area effect. Nudge resolves to suggestion or villager-startle interactions and deliberately does nothing to craters.
- `src/powers/outcomes.ts` maps every `InteractionKind` to a world/effect handler. The visual power modules own staging; outcome handlers own target-specific consequences and load-bearing discovery events.
- `src/powers/meteor.ts` implements Meteor's 1.2-second anticipation, one-frame impact, and aftermath timeline. Three radii have separate jobs: the 3-metre lethal target radius, the 4.5-metre blast ring whose startle hands off to a sprint, and the 4.5–9-metre safe ring that watches the sky. Impact coordinates the persistent crater/scorch staging, delegates target consequences to the interaction matrix, and emits a close-call event only after a living at-risk villager has run outside the lethal radius.
- `src/powers/lightning.ts` implements Lightning's curious-cloud anticipation and two-frame clay-white bolt. Strike staging makes the entire island flinch for one quantized beat, then delegates target consequences—including the nonlethal comic zap—to the interaction matrix.
- `src/powers/rain.ts` implements Rain's arriving cloud, six-second shower, departure, and half-second nurture ticks. Its radius-wide douse/fill/grow/bloom/grump behavior remains independent of target dispatch; the matrix adds its one-shot target flourish only on the first impact tick. First impact restores every intersected pond after crater filling, exactly once per cast, so later shower ticks cannot replenish a new catch.
- `src/powers/nudge.ts` implements the two-second-cooldown Nudge power and its brief, disposable paper-clay poke ripple. Ground intent is a weighted, place-aware roll over eligible actions rather than a first-match ladder: the ladder made `build` deterministic because the starting population already satisfies `living >= capacity()` where capacity is twice the built-hut count. A no-fire emergency still overrides the roll; build eligibility uses housing pressure, the six-hut cap, and `pendingSite()` hysteresis; tree and pond options sense within `NUDGE_SENSE_RADIUS`. Ground intent distinguishes stocked water (`fish`) from empty water (`drink`) and fruit trees (`harvest`) from bare trees (`chop`), keeping both tree choices available in a mixed stand. Direct Nudge on a fruiting tree always carries harvest intent for that specific tree. The result travels through the same outcome matrix as every other power.
- `src/discovery/moments.ts` is the Three.js-free definition and matcher for exactly fifteen teaching Moments. `Wildfire` watches `fire:ignited.bySpread`, `Firefighter` requires Rain to douse at least one actively burning object, `Drained` watches the previously unused `pond:emptied`, and the duplicate Full Harvest entry is retired in favor of `Fed`. `Journal` injects a storage-shaped interface, maintains multi-event counters and spatial crater matches, persists only ids validated against the current `MOMENTS`, and degrades safely on corrupt or unavailable storage. A retired id is filtered safely during load; surviving ids must never be renamed because that would revoke an existing unlock.
- `src/audio/sfx.ts` owns the sole lazy `AudioContext`, master mute persistence, ambient bed, six-voice cap, impact ducking, quantized step foley, synthesized power/fire/reward voices, and deterministic prologue growth/step/hammer/place/ignite profiles. Begin is the user gesture that lazily unlocks audio; Settings is the only mute-control surface.
- `src/prologue/choreography.ts` is the pure eleven-second cinematic timeline. It derives tree growth, three concurrent causal three-beat hut builds, three campfire placements plus ignition, six actor positions/poses/carries, cue crossings, and camera pose from elapsed time and the blueprint. Full motion holds target `(0, 0, 0)`, height `14`, and horizontal radius `34` while the camera moves at constant angular speed through a 180-degree orbit ending at `CAMERA_HOME`; reduced motion holds `CAMERA_HOME` for the full story while keeping the same duration and causal beats, completed geometry, and short opacity reveals instead of travel/growth tweens.
- `src/prologue/actor.ts` owns `PrologueActor`, an isolated `VillagerModel`, carried wood/stone, and optional reduced-quality blob shadow. It never imports `World` or the event bus and settles to its blueprint ground/facing before comparison.
- `src/prologue/prologue.ts` owns `PrologueSet` and `PrologueDirector`. Each session creates an independent blueprint-derived island, props, actors, and material piles; the director reason-locks the camera, dispatches crossed sound cues once, seeks idempotently to the exact final composition, and disposes all session geometry/materials. Named visible child transforms form `HandoffRecord`s and must equal the independently built gameplay records before the normal group swap.
- `src/prologue/audit.ts` provides framebuffer capture, campfire ember-mask projection, and the optional `?handoffAudit=1` comparison. The two held handoff renders freeze sky/stage bob, grain seed, camera shake, and camera matrix on the audit path; changes greater than two RGB levels outside the 64-device-pixel ember mask must affect no more than 0.1 percent of compared pixels.
- `src/ui/title.ts` owns the single semantic clay **Clay Island / Begin** plaque, first/returning prologue transport, and opaque replay covers. The normal Begin mode uses a translucent veil over the frozen time-zero prologue set; Begin animates the plaque away and continues that same director. First-view Skip is hidden and out of tab order, returning/replay Skip uses the same final-seek path, and cover completion is immediate under reduced motion or 320ms otherwise.
- `src/ui/settings.ts` owns the upper-right gear and one focus-trapped modal, anchored directly beneath and right-aligned with the gear, for Sound, Enhanced/Reduced quality confirmation, Auto-rotate, Reduced motion On/Off, Reset camera, and Replay intro. Opening it makes sibling UI inert, cancels targeting, closes Journal, and reason-locks the camera; Escape/backdrop/close restore trigger focus. Sound no longer belongs to the tray, forced low-FX disables the quality fieldset, and failed quality persistence reports inline without reload.
- `src/ui/tray.ts` creates the semantic powers toolbar from real buttons, owns shortcut arming and visual/accessibility state, and derives the Journal total from `MOMENTS.length`; its only auxiliary control is Journal. Cooldown fills remain quantized and guarded against redundant DOM writes; Nudge occupies the fourth slot and keyboard shortcut `4` with the same ARIA path as the destructive powers. Its glyph markup exposes wrist, palm, folded-finger, thumb, and extended-index clay parts so the small tray silhouette reads as a pointing hand in normal and disabled states.
- `src/ui/journal.ts` builds the queued discovery toast and the focus-trapped DOM clay tablet, including its hint surface and accessible 3×5 moment grid. Moments unlocked during the same update wait for the active toast to finish and are then shown in arrival order. Arrow-key row wrapping derives from the moment count, Escape restores journal-button focus, and background tray controls use `aria-hidden`/`tabindex` isolation instead of `inert` to avoid WKWebView compositor corruption. The journal does not touch the Three.js renderer.
- `src/ui/tokens.ts` is the design-token source of truth for the game palette, typography, and timing. Visual modules consume the exported string and numeric constants; the module remains independent of Three.js.
- `src/styles.css` defines the global scene UI, clay title/Begin seal, returning Skip, gear and Settings sheet, discovery toasts, gameplay reveal, hand-pressed clay journal and its moment dents, CSS-only pointing-finger Nudge glyph, narrow-layout collision avoidance, visible focus, and reduced-motion opacity/instant substitutions. Its custom properties mirror `src/ui/tokens.ts`.
- `index.html` owns the permanent canvas/UI/splash mounts, no-JavaScript fallback, product metadata, and the real in-engine OG share image reference.

## Key patterns

- Visual colors are named semantically in `PALETTE` rather than invented inside feature modules.
- Model animation uses the shared 12fps value in `TIMING`; UI transitions remain smooth and use separate durations.
- The full-screen `#ui` layer ignores pointer input by default, while its direct children opt back in.
- The full-screen journal layer accepts pointer input only while `.open`; its `[hidden]` state explicitly uses `display: none`, and closing disables hit testing immediately while the visual fade finishes.
- The live effective Reduced motion On/Off preference drives a root dataset and receives opacity-only or effectively instant CSS transitions. The prologue retains all eleven seconds and causal beats but holds the camera at home and uses fixed work compositions; auto-rotate stays disabled, camera reset snaps, and direct camera input remains available.
- Browser globals stay at the visual composition boundary; pure modules remain safe to exercise in Vitest's Node environment.
- Core simulation modules do not import Three.js. Seeded randomness, noise, event delivery, quantized time, and staged timelines are deterministic or directly unit-testable.
- Visual geometry is made irregular once at construction time, while the clay material supplies reusable surface character at render time. Both effects are procedural and require no asset files.
- `Island.sampleHeight()` is the single terrain-height authority. It combines the undeformed procedural surface with all active crater offsets so walkers and props cannot diverge from visible terrain deformation.
- Craters group transitively into one basin only when each link has a continuously submerged saddle: rim overlap alone remains separate if 0.5 metres of freeboard leaves visible dry ground between the water surfaces. Connectivity samples the same non-stacking cosine bowl depth used by terrain deformation at 0.1-metre intervals, so logical pond identity follows the rendered water. Every basin has one water level—the lowest of 48 circumference samples per exterior crater rim minus 0.5 metres of freeboard. `Pond` clips a flat top and terrain-following bed to actually submerged ground, `contains()` uses that same submersion rule, and `shoreNear()` chooses from the mesh's wet/dry boundary so dry banks and gaps between lobes are not treated as water.
- An ejecta lip can move terrain out to 1.45 times its crater radius. `Island.addCrater()` updates visible vertices and normals across that complete influence plus one mesh ring, keeping the rendered surface aligned with `Island.sampleHeight()`.
- `isBuildable()` is the common placement gate: candidate sites must be inside the walk radius, outside every crater, unsubmerged, below the maximum sampled slope, and clear of occupied props. The fixed-step terrain-validity pass abandons ruined huts and scatters intact or doused campfires when their existing ground becomes unbuildable, including when a pond submerges it. Choosing deferred work reserves valid ground invisibly so other placement cannot take it, while drowned foundations and scattered campfires remain visible. On builder arrival, `World` revalidates the reservation; success disposes the old remains and reveals the site, while failure disposes only the hidden target and leaves the old remains retryable.
- Island surface colors have two explicit layers: mutable `baseColors` hold grass, dirt fringe, and exposed crater soil; `scorchAmt` accumulates permanent radial burn strength and blends the visible color from that preserved base toward the scorch token. This prevents repeated paint from drifting past its intended color and keeps crater/scorch ordering stable.
- `InitialWorldBlueprint` is an immutable-data handoff boundary rather than shared mutable scene state. Its canonical prop list contains three built huts, and the prologue and gameplay each construct their own island, props, and villager models from the same ids and seeds; the prologue's final named visible transforms and states are compared exactly against gameplay records.
- `AppFlowState` is the sole phase authority. Illegal events return the same object without advancing generation; accepted transitions advance generation so delayed cover/director callbacks cannot install stale DOM or Three.js state. Fixed-step simulation and gameplay-only display updates are both gated by `simulatesGameplay()`.
- The scene-level `stageRoot` owns ambient island translation and contains gameplay, the current prologue set, and the shared particle pool. Effect origins are stage-local; scene-root sky and clouds remain independent. This keeps power particles attached to the bobbing island without leaking a temporary prologue transform into gameplay.
- Ambient stage and cloud motion consult the live reduced-motion preference; direct camera input remains enabled. Camera exploration changes the OrbitControls target rather than moving the island, and the target is clamped to a horizontal 7.5 metre disc.
- Normal rendering caps DPR at 1.5 and uses one 2048px VSM shadow map with radius 5 and 16 blur samples plus distance-adaptive tilt-shift, vignette, 12fps-held grain at 0.12 opacity, and a subtle saturation grade. Tilt is zero at close inspection and reaches its 0.45 cap at the home view. `?lowfx=1` fixes DPR at 1 and bypasses the shadow map and post composer.
- Film grain owns an explicit seed uniform rather than using `postprocessing`'s display-rate time uniform. It advances only on the shared 12fps cadence and becomes lower-opacity static grain under reduced motion.
- Repeated small object details use `InstancedMesh`, while stateful trees and huts remain independent object groups. In low-FX mode their child meshes stop casting map shadows and each grounded object receives one transparent blob-shadow disc; a falling tree shifts and stretches that disc between its root and offset log.
- Particle bursts claim dead slots from a single 400-instance pool under `stageRoot`, update matrices once per display frame, and use seeded randomness for launch vectors and tumbling. Callers provide stage-local ground height; the parent supplies ambient bob. Particles intentionally stay smooth while villagers and model props remain quantized to 12fps.
- Camera shake removes its prior offset before orbit controls update, then applies the next trauma-squared sample only for rendering. This prevents temporary shake offsets from contaminating OrbitControls' persistent camera state. Reduced motion clears the active offset and trauma immediately; reduced flash uses a 200ms fade-in/out capped at 30% opacity rather than a white strobe.
- Camera ownership is reason-based rather than one boolean: prologue, active targeting, Journal, and Settings can lock independently, and controls are enabled only when the last reason releases. User input cancels reset/recentre tweening; after eight idle seconds auto-rotate first recentres an offset target over 1.2 seconds, and reduced motion or the Auto-rotate setting prevents both behaviours.
- First and returning page loads both construct and freeze the canonical prologue's time-zero set behind the title, then continue that same set after Begin; only the first prologue is mandatory. First completion writes `clayisland.introSeen` after the held-frame handoff, so a failed or abandoned prologue remains mandatory next load. All three huts are built in the prologue and in the canonical gameplay handoff. The normal handoff renders the final prologue once, swaps to an independently built frozen gameplay world at exact home/stage rotation, renders it once, then enables simulation on the following frame.
- Settings replay never reconstructs gameplay. It records camera/stage pose, hides the gameplay island and frozen particle pool behind an opaque cover, runs and disposes one isolated canonical prologue, then restores the same island objects, transient-pool visibility, and pose behind the outbound cover. Title, Settings, canvas, and gameplay services remain singletons across repeated replay cycles.
- `?handoffAudit=1` turns the two normal handoff renders into a measurable invariant: ambient movement, camera shake, camera controls, and held grain stay frozen; framebuffer comparison ignores only the projected campfire ember mask and reports pass/fail in the console.
- Every power is a three-beat `Timeline`: anticipation communicates intent and triggers reactions, impact coordinates spectacle and world mutation, and aftermath leaves consequences. `PowerManager` starts cooldown at cast time and owns timeline/cooldown advancement; visual actors own and dispose their transient Three.js resources.
- Power staging and target consequences are deliberately separate: each power resolves a pure matrix cell and `OUTCOME_HANDLERS` applies the resulting declarative interactions. Rain's area weather effect stays outside that table so a cast aimed at one target still affects the whole radius.
- Journal and Sfx are independent subscribers to the existing event stream; neither requires powers or `World` to know about discovery or audio.
- The journal is one DOM structure in every rendering mode. A clipped outer crust and inset face give its slab a deterministic hand-cut silhouette, while restrained grain and compression marks keep the surface clay-like. Tiles vary their radii, dent offsets, and compression centers without tilting their text. Locked tiles are pale raw-clay recesses with dark inset top-left and light inset bottom-right; unlocked tiles preserve that recess underneath a raised clay cap whose semantic moment color is mixed with the paper clay, so water, fire, bloom, harvest, and stone remain recognizable but belong to one earthy pigment set. `lowFx` and the root effective reduced-motion state only skip the journal's smooth press-in transition.
- The previous 3D journal was removed because a head-on orthographic camera made its 140° cover swing render edge-on as a narrow splinter, while the shadow-catching desk plane filled the scissored viewport and erased the object's silhouette. The journal stays DOM-native so those structural failures cannot return.
- Rainfall is allocation-bounded during play: droplets and ripples are fixed-size `InstancedMesh` pools whose matrices are rewritten at render time, while cloud geometry is allocated once per cast and disposed after departure. Its consequence ticks are intentionally discrete at 0.5 seconds so area effects remain legible and idempotent.
- Pond fish are a bounded visual resource owned entirely by `Pond`: meshes are allocated once, fishing hides one, Rain reuses and restores them, and Lightning changes only their temporary presentation. Availability is checked again at FSM selection, target acquisition, and mutation so simultaneous fishers cannot produce phantom catches. Nudge suggestions carry intent rather than a time-to-live; priority overrides preserve them, while completion or target invalidation clears them explicitly.
- Wildfire simulation is Three.js-free and uses only `FIRE_CONFIG`, stable `Flammable` records, fixed-step `dt`, and a dedicated seeded RNG. Burn-out is processed before spread, and the spread-source list is snapshotted so a newly ignited object cannot cascade again in the same tick. `World` applies returned events to visual objects and the shared game bus, keeping simulation, effects, villager alarms, and discovery counts synchronized.
- Forest recovery is displacement rather than resurrection. A chopped tree topples for 0.6 seconds while moving its trunk to a 0.9-metre offset, holds the resulting beside-the-stump log for 30 seconds plus a two-second fade, then holds and fades its stump for the same durations. A burned tree shares the fall, offset, and log timing but leaves no stump; a meteor removes its target immediately. `World.reseedForest()` grows a new sapling near surviving standing trees whenever fewer than 13 hold a place, with an island-wide mercy site if none survive. All placement randomness comes from `RNG`.
- Fire fuel and forest capacity remain separate named policies but currently select the same states: `sapling`, `normal`, and upright `burning`. Toppling begins only after the 12-second burn has completed; `toppling`, `felled`, and `stump` satisfy neither policy. `Charring` is the only material-color path for trees and huts, so burning affects every owned material and extinguishing or rebuilding restores the captured base colors.
- Fire visuals allocate their clay blobs, smoke, and point lights once per object and only toggle/update those reusable children. At render time `World.updateFireLights()` sorts the lit campfire plus burning objects by camera distance and enables no more than three shadowless fire lights.
- Spatial target resolution is intentionally ordered and linear: living villagers, trees, huts, an intact campfire, basin-shaped ponds, craters, then ground. Dead historical villagers, scattered campfire debris, and dry land inside a basin's bounding radius cannot mask visible targets. The registry remains small enough that a spatial index would add complexity without practical benefit.
- Villager decisions use hard narrative triggers before a weighted idle roll: nearby fire overrides every activity, then fresh graves and rebuildable ruins; only currently available idle actions—including reserving deferred hut/campfire work, relighting an intact fire, harvesting fruit, or gathering—enter the seeded random selection. A Nudge suggestion keeps `SUGGESTION_WEIGHT` at 30, adding strong preference without making an impossible action eligible, bypassing an emergency, or becoming a command. Perceived strength comes from reach instead: `World.suggest()` tags up to four eligible villagers within `NUDGE_EARSHOT`. The reservation is invisible during travel, and visible site creation occurs only when the villager arrives to start work. Thirst is a separate interrupt/resume need rather than an idle utility score.
- Villager coordinates and timers advance on the fixed 30Hz simulation step, but model positions, facing, waddles, work poses, spawn scale, and emote animation are written only when the 12fps clock changes. This intentional one-frame visual lag is the claymation effect.
- Villager movement uses direct steering plus short-range repulsion from registered solid objects, four-sample pond-depth repulsion, a stable shoreline tangent, and a hard `WALK_RADIUS` clamp. Random wandering and panic fan-out reject submerged targets. Water is an obstacle only: it never damages or removes a villager, and there is intentionally no navmesh or pathfinding.
- Population is housing-gated and self-healing: `World.repopulate()` waits a seeded 20–30 seconds before spawning one replacement only while the living count is below two times the number of built huts, capped at 12. Destroying housing can create a stable over-capacity village but never culls or evicts anyone. If no villager and no built hut survive, a site, in-progress build, rebuildable ruin, or finally an abandoned foundation becomes the last-resort mercy origin and ignores capacity so deferred construction cannot deadlock. Living survivors still rebuild normally instead of spawning from those fallbacks. Dead entries remain in the registry for later grave/discovery history while living-count and targeting checks ignore them.
- Power targeting is modality-independent after arming: pointer rays and keyboard steps both update the same island-local target coordinates, reticle, target-kind lookup, and fire callback. Returning to the originating power button enters an explicit cancel preview; releasing there or away from the island cancels, while moving away restores targeting. Keyboard Escape cancels and restores tray focus.
- Power cooldowns are normalized values at the tray boundary. The manager registers Meteor, Lightning, Rain, and Nudge at six, three, eight, and two seconds respectively; all four controls share the same pointer/keyboard targeting and ARIA cooldown path.

## Classes and database schema

The project-defined classes are `RNG`, `EventBus`, `GameLoop`, `QuantizedClock`, `Timeline`, `Preferences`, `CameraController`, `VisualQualityController`, `FireSystem`, `Charring`, `Island`, `Tree`, `Hut`, `Campfire`, `Pond`, `Grave`, `FlowerPatch`, `World`, `EmoteSprite`, `VillagerModel`, `Villager`, `PrologueActor`, `PrologueSet`, `PrologueDirector`, `DragTargeting`, `ParticleBurst`, `Shake`, `Power`, `PowerManager`, `Meteor`, `Lightning`, `Rain`, `Nudge`, `Journal`, `Sfx`, and the scene-private `HeldNoiseEffect`. `AppFlowState`, `InitialWorldBlueprint`, and `HandoffRecord` are pure data contracts rather than classes. `World` stores typed tree, hut, villager, grave, pond, and flower-patch arrays plus one campfire. Fire simulation operates on the in-memory `Flammable` shape; forest placement operates on the pure `Seedling` shape; villager suggestions use the in-memory `Suggestion` shape.

There is no database and no island-state persistence: terrain mutations, villagers, buildings, fire, camera pose, cooldowns, and replay state are runtime-only and reset on reload. Cross-reload storage is limited to:

- `localStorage['clayisland.moments']`: validated JSON array of Moment ids;
- `localStorage['clayisland.muted']`: boolean string owned by `Sfx`;
- `localStorage['clayisland.visualQuality']`: `enhanced | reduced` owned by `Preferences`;
- `localStorage['clayisland.autoRotate']`: boolean string owned by `Preferences`;
- `localStorage['clayisland.reducedMotion']`: guarded boolean string owned by `Preferences`, defaulting from the OS only until an explicit valid value is stored; and
- `localStorage['clayisland.introSeen']`: boolean string written only after the first mandatory normal handoff.

All storage access is optional and guarded; Three.js scenes, meshes, materials, framebuffer audit pixels, and audio nodes remain runtime-only.
